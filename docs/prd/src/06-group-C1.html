10Screens and User Experience

The resident and administrator use the mobile app (screens S-xx). Guests use a browser page (W-xx) that needs no install. A registered guest can see the same invitation inside the app (S-11). The administrator uses the same app as residents, with an extra "Community" area. Language: Hebrew UI with right-to-left layout as the primary language, and English as a Could (NFR-17).

What it shows: the main path through the screens in the table above. A resident signs in, creates a permission with the form or the wizard, and shares the link. The guest opens it in a browser (or in the app through a deep link) and requests an opening. A grant shows up in the resident's Activity screen. Why it matters: it confirms that the guest's path from link to opening is a single page with one tap (G4), and that the screen IDs match the table and the wireframes.

About the wireframes: they are low-fidelity sketches in grayscale with no visual design. They show only what sits where on each screen. The final UI will be Hebrew, right-to-left. These sketches are drawn left-to-right in English so the PRD reads consistently.
