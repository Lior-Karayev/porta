14Assumptions, Constraints, Dependencies and Risks

14.1 Constraints

  • Time: about 10 weeks from this PRD (21 Nov 2026) to the MVP deadline (31 Jan 2027). The period overlaps other courses and the end-of-semester exam season.
  • Team: three members (Daniel, Lior, Avishag). Their roles are not yet assigned (Q-01).
  • Knowledge: the team is learning Flutter/Dart during the course (assumed limited prior experience).
  • Budget: zero by default. Any paid service (cloud billing plan, Apple developer account, LLM API, custom domain) needs explicit team approval, with cost, benefit and alternatives stated.
  • Hardware: no real gates. Everything is simulated.
  • Course: the app must be developed in Flutter/Dart and delivered according to the course checkpoints.

14.3 Dependencies (external services the product relies on)

  • A Backend-as-a-Service for authentication, database, server functions and hosting (A-03). Note: Firebase Cloud Functions require the pay-as-you-go (Blaze) plan with a linked billing account, even within free usage quotas. That is a budget decision (Q-09).
  • Push delivery: FCM for Android, and APNs for iOS, which requires an Apple developer account.
  • Domain and HTTPS hosting for invitation links and link-verification files (Q-15).
  • The Apple Developer Program, for iOS device deployment, Universal Links and push (R-04).
  • Flutter SDK and open-source packages (QR rendering, secure storage, deep links).
  • LLM API provider: only for FR-35 (Could), and only after approval.

14.4 Risks and mitigations

IDRisk: what could go wrongLikeli-hood / ImpactProposed mitigation: what we will do
R-01The schedule slips: the team is new to Flutter, and January has exams.H / HStrict MoSCoW: cut Should items before touching Must. Fixed milestone dates (Section 15). A weekly progress check, and an early vertical slice (M2–M3) before polish.
R-02An invitation link is forwarded, and someone else uses it.M / MTime and count limits bound the damage. Instant cancel or regenerate (FR-11, FR-17). Entry notifications (FR-29). Optional PIN or proximity check in future (Q-13).
R-03Concurrent or retried requests double-count or exceed the limit.M / HAn atomic server transaction plus a unique request ID (NFR-07). Concurrency tests (AC-08.4).
R-04iOS features (Universal Links, push, deployment to devices) need a paid Apple developer account (USD 99 per year, per Apple's published pricing).H / MAndroid is the guaranteed demo platform. Use the iOS simulator without push. Ask the college about an education account. Paying requires team approval (Q-10).
R-05The backend's free tier doesn't cover server functions, or a billing account is required.M / HDecide by the start of M1 (Q-09). Develop against the free local emulators until then. Option 1: approve the Blaze plan with budget alerts. Option 2: switch to Supabase Free, with one transactional database function (Section 11.3). A cost estimate is due before any approval.
R-06The AI feature produces wrong drafts, costs money or is unavailable.M / LKeep it as a Could. Confirmation before saving, server re-validation, an 8 s timeout and a manual fallback (Section 11.4).
R-07Time-zone or daylight-saving bugs grant or deny at the wrong hour. Israel changes clocks in late March and late October.M / HEvaluate only on the server, in the community's time zone, with a time-zone library. Add test cases around the DST change dates.
R-08A Flutter Web guest page is too heavy to meet NFR-02 (≤ 3 s, ≤ 1 MB).M / MProposed: a lightweight HTML/JS guest page instead of Flutter Web, decided in M1 (Q-14).
R-09Deep-link verification is hard to set up.M / LIt is a Should. The web fallback works for everyone (AC-09.2).
R-10Push notifications are delayed or not delivered.M / LThe in-app Activity log is the source of truth. Push is a convenience.
R-11The problem or solution doesn't match real residents' needs (no research yet).M / MA validation round with at least 5 residents (Q-02) before M4. Update defaults and priorities from the findings.
R-12Someone guesses tokens or probes links.L / H128-bit tokens, hashed storage, rate limiting and a generic invalid page (NFR-05, NFR-06).
R-13Responsibilities are unclear, so work is duplicated or gaps appear.M / MAssign roles (Q-01) before M1 begins. Track tasks in GitHub issues.
